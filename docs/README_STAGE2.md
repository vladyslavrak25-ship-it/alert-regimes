# Alert Regimes — урок 2: режими активності

## Як запустити в PyCharm (Windows)

У теці проєкту, де вже знаходяться `data.py` та `run_data.py`, мають бути нові файли:

- `regimes.py`
- `run_regimes.py`
- `tests/test_regimes.py` (усередині існуючої папки `tests`)
- `README_STAGE2.md` (ця інструкція)

**Не видаляйте** `data`, `outputs`, `data.py` і `run_data.py`.

У нижній панелі PyCharm відкрийте **Terminal**, переконайтеся, що командний рядок показує папку вашого проєкту, і виконайте:

```powershell
python -m pytest -q
python run_regimes.py
```

Оскільки на попередньому етапі вже створено `outputs/daily_alert_hours.csv`, запускати `run_data.py` знову не потрібно. Якщо добового файлу немає, спочатку виконайте `python run_data.py`.

## Що генерує програма

- `outputs/regime_thresholds.csv`: пороги 33-го й 75-го перцентилів **лише на 16.03–11.09.2026** для областей, що пройшли правила.
- `outputs/train_regimes.csv`: таблиця категорій лише для навчального періоду (не для тестових дат).
- `outputs/region_readiness.csv`: для кожного кандидата — обсяг історії, активні дні, відсоток умовних годин, кількості кожного класу, рішення щодо придатності.
- `outputs/regime_manifest.json`: дату створення, контрольну суму вхідної добової таблиці, періоди та використані правила.

## Що означають категорії

- **Низька**: тривалість ≤ 33-го перцентиля попередньої навчальної історії області.
- **Помірна**: між 33-м і 75-м перцентилями включно у верхню межу.
- **Висока**: вище 75-го перцентиля.

Це **відносні рівні зафіксованої тривалості**, а не офіційні жовтий/червоний сигнали, і не оцінки безпеки.

## Як ми контролюємо data leakage

Пороги, кількості класів та правила придатності обчислюються виключно за період **16 березня — 11 вересня 2026**. Дати **12 вересня — 9 жовтня 2026** зарезервовані для подальшої перевірки моделей і не входять до `train_regimes.csv`.

Усі умови придатності — попередні інженерні правила, а не гарантія якості прогнозування. Рядок із 0 годинами позначає відсутність інтервалу в джерелі, а не підтверджений безпечний день.

Під час подальшого backtesting, якщо модель навчається на ранніших історичних вікнах, пороги мають обчислюватися окремо з історії кожного вікна. Не можна повторно використовувати наші пороги від 11 вересня для оцінювання старіших прогнозів, якщо на момент тих прогнозів пороги ще не могли бути відомі.
